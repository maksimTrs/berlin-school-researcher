Адреса: $ARGUMENTS

Если адресов нет — возьми `defaultAddress` из `config/config.json`.

## 1. Разбор ввода → `input.json`

Раздели ввод на адреса по `;` или переносу строки (не больше `maxAddresses` из `config/config.json`, лишние — назови и пропусти).
Для каждого адреса восстанови немецкое написание и заполни поля:

```json
{ "addresses": [
  { "raw": "каштаналее 12 пренцлауэр", "street": "Kastanienallee", "house": 12,
    "suffix": null, "plz": null, "ortsteil": "Prenzlauer Berg" }
] }
```

- `street` — немецкое название улицы; «str.», «strasse» можно оставить как есть, код их нормализует. Кириллицу транслитерируй по звучанию: «бергманнштрассе» → `Bergmannstraße`, «каштаналее» → `Kastanienallee`.
- `house` — число, `suffix` — одна буква («44F» → 44 + `"F"`), иначе `null`.
- `plz` — только если в вводе есть 5 цифр. `ortsteil` — район/Ortsteil, если упомянут («пренцлауэр» → `Prenzlauer Berg`, «Kreuzberg»).
- Не выдумывай PLZ и район, которых нет во вводе.

## 2. Проверка адресов

`npm run resolve -- --input input.json` → `resolve.json`, у каждого адреса `status`:
- `exact` — дальше.
- `ambiguous` — кандидаты в разных районах. **Не выбирай наугад.** Покажи пользователю список «улица, дом, PLZ Ortsteil (Bezirk)» и спроси, какой. После ответа впиши `plz` выбранного кандидата.
- `none` — покажи, как ты понял адрес, предложи 1–2 вероятных исправления написания и проверь их тем же `resolve`. Если не помогло — спроси пользователя.

## 3. Отчёт

Перепиши `input.json` только с однозначными адресами и запусти `npm run lookup -- --input input.json`
(по ~20–40 с на адрес; в облаке запускай с таймаутом 10 минут). stdout — JSON-массив сводок, по одной на адрес, с путями `report` и `result`.

Перед браузером `lookup` сам проверяет критичные источники (WFS адресов, зон, школ и Schulverzeichnis):
- stdout `{"preflight": "failed", "checks": [...]}`, exit code 2 — отчёты не строились. Назови пользователю недоступные источники с их `error` и остановись. В облачной сессии добавь: возможно, окружению нужен Network access **Full**.
- У отдельного адреса `status: "error"` (exit code 1) — остальные адреса обработаны: опубликуй их отчёты, а для упавшего покажи `error` и предложи повторить.

Не пытайся собрать отчёт вручную.

## 4. Публикация

Каждый `report.html` — **отдельный новый artifact**: Artifact tool, `file_path` = путь `report` из сводки, `icon: "school"`,
`description`: «Закреплённая школа и показатели Schulporträt для <адрес>». HTML отчёта не правь — его генерирует код.

## 5. Итог в чат

На каждый адрес 3–5 строк из сводки lookup:
- школа и номер; статус сопоставления (`exact` / `override` — без пометок; остальное — ⚠️ и кандидаты, «уточнить в Schulamt района»);
- Ausfall уроков текущего года против Берлина (`ausfall`, `ausfallBerlin`);
- ⚠️ альтернативы адреса, если были;
- ссылка на artifact.

Дальнейшие вопросы по отчёту отвечай по `result.json` того же адреса. Цифры — только оттуда; нет значения — «н/д — нет данных на сайте за <год>». Ничего не досчитывай и не оценивай.
